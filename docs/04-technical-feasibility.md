# 04 — Technical Feasibility

Verdict per platform on whether a Lifesycle-initiated, genuinely one-click live broadcast is achievable via official, sanctioned APIs. Full API details are in [05-api-research.md](05-api-research.md).

## Summary table

| Platform | One-click native start? | Mechanism | Verdict |
|---|---|---|---|
| **Facebook Live** | ✅ Yes | Graph API Live Video API, RTMPS ingest, app requests "Live Video Publishing" permission | **Feasible — build for MVP** |
| **YouTube Live** | ✅ Yes | YouTube Live Streaming API (`liveBroadcasts`/`liveStreams` insert), RTMPS ingest | **Feasible — build for MVP** |
| **Zoom** | ✅ Yes (as a source, not a destination) | Zoom's built-in Live Streaming app / Video SDK RTMP output can restream a Zoom session out to a custom RTMP target | **Feasible — build for MVP**, used as an ingest source or restream hub, not a "social" destination |

| **Instagram Live** | ❌ No | No public API to programmatically start a broadcast. ## Detail per platform

### Facebook Live — feasible
Facebook's Live Video API accepts an RTMPS stream at a single combined server+key URL (`https://live-api-s.facebook.com:443/rtmp/`), reachable over standard outbound port 443, which a Lifesycle-hosted encoder/relay can push to without any user-side software [[Meta Live Video API]](https://developers.facebook.com/docs/live-video-api/). Requires the app to hold "Live Video Publishing" permission and go through Meta's standard app review. This is the strongest candidate for true single-click start: Lifesycle can generate the stream key server-side and begin publishing the instant the agent clicks "Go Live."

### YouTube Live — feasible
The YouTube Live Streaming API exposes `liveBroadcasts.insert` (create the broadcast) and `liveStreams.insert` (obtain the RTMPS ingest URL/key), which is exactly the create-then-push pattern needed for a one-click flow [[YouTube Live Streaming API]](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts) [[RTMPS ingestion guide]](https://developers.google.com/youtube/v3/live/guides/rtmps-ingestion). Standard OAuth consent (channel owner authorizes Lifesycle once), then no further manual steps per broadcast. Quota is a real constraint to validate against Google Cloud Console allocations before committing to a per-agent, per-broadcast usage pattern at scale, but the mechanism itself is sound.

### Zoom — feasible (as a relay/source, not a "social platform")
Zoom's Live Streaming app can push a meeting or webinar to up to three RTMP destinations (Facebook, YouTube, Twitch, or custom) simultaneously, and the Video SDK supports RTMP output for unlimited-audience restreaming beyond the 1,000-user real-time cap [[Zoom Live Streaming multistream]](https://onestream.live/blog/multistream-your-zoom-meetings-webinars-for-wider-outreach/) [[Zoom Video SDK live streaming]](https://developers.zoom.us/docs/video-sdk/web/live-stream/). Practically, Zoom is most useful in this product as an *ingest source* for private/1:1 valuation calls or agent-hosted webinar-style opens that Lifesycle then optionally relays outward — not as a "go live to my Zoom audience" destination in the way Facebook/YouTube are.

### LinkedIn Live — partial
LinkedIn requires broadcasters to either use one of a short list of preferred third-party broadcast partners or pass a manual eligibility review to unlock generic RTMP ingest ("advanced broadcasters... can connect directly to any streaming software or encoder using a custom stream") [[LinkedIn Live partners]](https://business.linkedin.com/content/dam/me/business/en-us/marketing-solutions/products/pdfs/linkedin-live-3rd-party-broadcast-partners-chart.pdf) [[LinkedIn Live access via preferred partners]](https://www.linkedin.com/help/linkedin/answer/a520811). As of June 2026, all LinkedIn Live events must be scheduled in advance — spontaneous "go live now" is no longer possible on LinkedIn at all, which caps how "one-click, right now" this integration can ever be, independent of Lifesycle's own engineering [[LinkedIn advance scheduling]](https://www.netinfluencer.com/linkedin-to-require-advance-scheduling-for-all-live-streams-starting-june/). Realistic approach: Lifesycle applies for RTMP-ingest eligibility as a broadcast tool in its own right (the same posture as StreamYard/Restream), which is a business-development/approval task, not a pure engineering one.

### Instagram Live — not feasible as one-click
There is no general public API for third parties to programmatically start an Instagram Live broadcast. Instagram's own "Live Producer" supports custom RTMP ingest, but it is a feature of Instagram's own live-creation tooling for Business/Creator accounts, not an endpoint a third-party app can call to trigger a stream on the user's behalf [[Instagram Live Producer]](https://about.instagram.com/blog/tips-and-tricks/instagram-live-producer). The Instagram Graph API more broadly has hardened in 2026 — personal accounts are excluded entirely, only Business/Creator accounts can connect, and rate limits are tight (~200 calls/hour, 25 published posts/24h) [[Instagram Graph API 2026]](https://www.netrows.com/blog/instagram-graph-api-guide-2026) [[Instagram API Pricing 2026]](https://www.getphyllo.com/post/instagram-api-pricing-explained-iv). **Recommended MVP posture**: the agent starts the Instagram Live natively in the Instagram app; Lifesycle offers pre-live prep (talking points, promo asset) and, where the Graph API permits, pulls comments/engagement after the fact rather than live-moderating in real time.

### TikTok Live — not feasible, and access is unstable even for chat
TikTok publishes no official public API for live-broadcasting or live chat data at all; everything available (`tiktok-live-connector`, `TikTokLive` Python library, `tik.tools`) is an unofficial reverse-engineered client hitting TikTok's internal WebCast protocol [[TikTokLive GitHub]](https://github.com/isaackogan/TikTokLive) [[TikTok LIVE API guide]](https://www.eulerstream.com/what-is-tiktok-live). This is materially riskier than the other platforms: in January 2026 TikTok revoked third-party PC streaming access for Streamlabs, StreamElements, and Restream.io simultaneously, with TikTok itself acknowledging the disruption but not the cause [[Streamlabs TikTok access revoked]](https://support.streamlabs.com/hc/en-us/articles/35259691237147-Streamlabs-x-TikTok-Streaming-Access-Revoked-Suspended). **Recommendation**: do not build production dependency on any unofficial TikTok integration. Treat TikTok as agent-native-only (agent goes live in the TikTok app) with, at most, an optional and clearly-labelled "experimental" chat-capture add-on the product can disable without notice if TikTok changes course — never a load-bearing part of the MVP.

## Product implication

"Single-click broadcasting across all platforms simultaneously" should not be the MVP promise. The defensible MVP promise is: **"Start your Facebook, YouTube, and Zoom-sourced live broadcast with one click from Lifesycle, with full CRM capture — and get AI-assisted prep and post-event automation for every platform you go live on, including Instagram, TikTok, and LinkedIn, even when you start those natively."** This is both honest about platform constraints and still meaningfully differentiated from every current alternative (see [03](03-competitor-analysis.md)).
